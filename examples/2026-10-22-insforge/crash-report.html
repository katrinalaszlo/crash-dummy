PASS Scenario 1: happy path

Sign up returned a session, three inserts, select/order, update, image upload to a public bucket (url + key returned), public fetch 200, SDK download 179 B. Same flow repeated in the browser dummy with an image attached.

PASS* Scenario 2: limits

Wrong password → 401 AUTH_UNAUTHORIZED, duplicate email → 409 AUTH_EMAIL_EXISTS, missing bucket → 404 STORAGE_NOT_FOUND, no key → 401 with a nextActions hint. *Missing table → 404 with body {}: the SDK error is an empty object.

PASS Scenario 3: config change mid-run

Operator flipped note-images to private in the dashboard. The running dummy's image went 401 immediately; anon download → 403 FORBIDDEN; the signed-in user's download still returned bytes.

PASS* Scenario 4: operator CRUD

Table created with typed DDL in the SQL Editor (green toast). Bucket created and edited. Invalid bucket name surfaced inline and as a toast. *Empty bucket name: silent no-op, dialog stays open.

FAIL Scenario 5: anon-key isolation

A signed-out client using only the public anon key selected, inserted and deleted rows in notes. pg_class.relrowsecurity = false; anon holds INSERT/SELECT/UPDATE/DELETE. The FAQ says new tables have RLS on by default — that holds for the API create-table path, not for DDL run in the SQL Editor, which is the path a self-hoster without MCP is left with. The Policies view shows "No policies found" and no RLS-off warning.
